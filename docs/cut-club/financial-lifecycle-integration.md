# CUT CLUB integrated financial lifecycle (disposable SQL only)

This draft combines #331 and #332 on their verified common base. Existing per-component CI remains intact; a new dedicated localhost SQL 2022 workflow installs both staging-only schemas and tests the actual purchase and claim transaction adapters together. No production migration, flag changes or deployment. The mocked session simulates a verified member; invoice rows are minimal synthetic fixtures, not the full POS payment HTTP flow. A passing run does not authorize real staging or production. Before release: integrate #329/#330, validate full authenticated POS payment paths against isolated staging, reconcile historical vouchers and reviewed service mappings, prepare reviewed production migrations and obtain separate approvals.

The purchase transaction now locks and revalidates the persisted session, tenant, access status and current linked phone before spending or replay and immediately before returning to commit. The new gate requires moderation schema (027); missing schema fails closed. Disposable financial fixtures model the required columns and test stale preflight state. This is not a substitute for deploying approved migration 027 or for actual authenticated POS acceptance.
