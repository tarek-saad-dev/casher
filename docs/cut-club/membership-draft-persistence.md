# Membership draft persistence (staging only)

Append-only tenant-scoped program revisions with server-sourced staff actor and mandatory reason. A stale expected revision fails with HTTP 409; a tenant transaction lock serializes creation/update. The pilot uses only approved branch IDs 1/3; no broad all-branch scope. No activation or financial fields, no default benefits, no real membership issuance. API and transaction require exact `last132_agent` / `drvo_agent`, pilot tenant and `CUT_CLUB_STAGING_MEMBERSHIP_DRAFT_ENABLED=true`. DDL is not registered as a production migration; do not run on last132. No SQL was applied by this PR. Follow-up: disposable SQL acceptance, evidence approval/revocation tied to a verified account, authoritative branch/visit proof, production migration sequencing after 027 and business approval. UI is disabled if staging backend is unavailable.
