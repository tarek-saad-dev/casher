# Benefit usage ledger — simulation only

A serializable, tenant-locked ledger records one service line per unique synthetic receipt UUID. It is intentionally not an invoice table or POS endpoint. Current application-bound trial, linked client, current publication and approval, proof, visits, branch (same as issued trial), current catalog price and per-trial/service usage limits are checked server-side. Limits persist across benefit approval revisions within the same trial; no stacking, split receipts or multiple lines are supported. Reversal is append-only, idempotent, and restores simulated capacity; no voucher/coin/cash or invoice mutations. A receipt cannot be reused after reversal. Existing independent trial sandbox does not qualify. Price is the global catalog price, not an invoice price. Must still integrate authoritative invoice identity, line prices, actual sale/void atomicity, multiple memberships/stacking policy, and audit/authorization before actual POS activation. Exact stage DB/login and off-by-default feature flags.
