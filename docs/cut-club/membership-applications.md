# Membership applications (staging only)

A verified linked member can submit a request for a current published revision and a permitted branch. One request per account/program/publication, replay returns the existing ID; a different client/branch conflicts. Account and session revalidated inside the transaction. Staff can record a one-time acceptance for further verification or rejection, with actor/reason; acceptance is NOT activation, approval of evidence, or financial entitlement. Withdrawn or superseded publication renders pending/accepted requests non-actionable. No raw documents or student institution data captured here; demographic collection and final proof review remain separate. Exact staging DB/login, off-by-default flags. Admin queue currently bounded to latest 100 with hasMore; pagination needed before release. No live DDL or deployment. Dedicated SQL acceptance and application-to-proof UI follow-up required.
